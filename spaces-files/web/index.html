            Help: the fields of this page
            
	
            
		
            spaces-files keeps files for people and agent instances. Every person and every agent is an actor with an ID of its own and a home, its own workspace. Shared work lies in workspaces, top-level directories. Hovering over a field, or focusing it, shows a short description above it; this page explains them in detail.
            

		
            Roles and inheritance
            
		
            
			
            viewer
            Reads files and lists directories.
            
			
            editor
            Everything a viewer can, and writes files, creates and removes files and directories.
            
			
            owner
            Everything an editor can, and gives and revokes grants, restricts directories.
            
		
            
		
            A role comes from a grant directly on a directory, from a grant to a group the actor belongs to, or from a directory above: roles apply to everything below. Several ways add up; revoking one takes away only that one. A workspace is visible exactly when one has at least viewer on its top. Without access, every path in it answers like a path that does not exist.
            

		
            Header
            
		
            
			
            You in tenant
            Your actor ID and the tenant (an isolated organisation or team) you are signed in to.
            
			
            Administration
            Opens the tenant administration below; shown to tenant administrators only.
            
			
            Switch tenant
            Signs in again; if your sign-in belongs to several tenants, you choose one.
            
			
            Sign out
            Ends this session on this device.
            
			
            ☾ / ☀ and the palette
            Dark or light mode and the colours of the PHI-SPACES palettes; kept in this browser.
            
		
            

		
            Workspaces and files
            
		
            
			
            Workspaces
            Every workspace you see. A click opens it; the line below shows where you are, .. goes up one directory. A directory marked (restricted) does not inherit roles from above.
            
			
            name, New file, New directory
            Creates an empty file or a directory in the directory shown. Names are case-sensitive, have no slash and are not . or ..; you need editor there.
            
		
            

		
            Grants on this directory
            
		
            
			
            The list
            Who holds which role directly on this directory, e.g. editor: group:north#member (every member of the group north). Only owners see it.
            
			
            Role (viewer, editor, owner)
            The role to give or take back. A viewer grant below the top of a workspace is refused: viewer on the top already reaches everything below.
            
			
            Kind (user, agent, group)
            Who receives the role: one person, one agent instance, or every member of a group.
            
			
            actor ID / group
            The actor's ID as the tenant's actor list shows it (without user: or agent:), or the group's name.
            
			
            Grant / Revoke
            Gives the role, or takes back exactly this grant. Every workspace keeps at least one direct owner, so the last one cannot be revoked.
            
			
            Restrict / Unrestrict
            Below the top of a workspace: a restricted directory takes no viewer or editor roles from above, only owners from above keep it; who else should reach it needs a grant on it. Unrestrict lets the roles from above pass again.
            
		
            

		
            Editing a file
            
		
            
			
            Save
            Saves your text over the version you opened. If someone else saved in between, the save is refused as a conflict and your text stays in the editor.
            
			
            Load their version
            After a conflict: shows the newer version; you then decide whether to save your text over it.
            
			
            Close
            Closes the file; asks first if there are unsaved changes.
            
			
            Remove file
            Deletes the file; refused if someone saved a newer version than yours.
            
		
            
		
            Files that are not text are downloaded instead of opened.
            

		
            Tenant administration
            
		
            Only for tenant administrators. Being an administrator gives no rights on files: an administrator reads a workspace only with a grant like anyone else.
            
		
            
			
            Register an actor: user / agent
            user is a person who signs in in the browser, agent an agent instance that works through an agent host (a program that connects to this service and acts for its agents).
            
			
            actor ID
            The ID the actor has in this tenant, used in grants and groups: 1 to 128 characters of A-Z a-z 0-9 _ . : -. An ID is never reused, even after the actor is deleted.
            
			
            home name
            The name of the workspace the actor gets for itself, created in the same step with the actor as its owner; usually the same as the actor ID.
            
			
            issuer / host peer ID
            For a user: who confirms the sign-in. With username and password this is local; with an OpenID provider, its issuer URL. For an agent: the peer ID of the agent host it runs on, enrolled by the host operator.
            
			
            subject / agent ID
            For a user: who the person is at that issuer, with username and password the username (lower case). For an agent: the agent ID its host gives it.
            
			
            Register
            Creates the actor and its home. A user signing in with username and password also needs a password; the host operator sets it on the server: npm --prefix spaces-files run docker:operator -- set-password <username>.
            
			
            Group membership: group
            The group's name. A group needs no creating: it exists as long as it has members or grants.
            
			
            user / agent / group, actor ID / group
            Who joins or leaves: an actor by its ID, or every member of another group by the group's name (groups nest up to 4 levels; a group cannot contain itself).
            
			
            Add / Remove
            A member gets every role the group holds; removing ends the access that came through the group at once, also for files already open.
            
			
            Create a workspace: name
            A new shared workspace. Names starting with @ are reserved for read-only mounts.
            
			
            user / agent, owner's actor ID
            Its first owner, who then gives the further grants.
            
			
            Actors, Groups
            Every actor of the tenant with its state (enabled, disabled) and every group.
            
		
            
		
            Every change is applied once, even if a reply is lost on the way and the page sends it again.
