            Help
            
	
            
		
            spaces-files keeps files for people and agent instances. Every person and every agent is an actor with an ID of its own and a home, its own workspace. Shared work lies in workspaces, top-level directories. Hovering over a field, or focusing it, shows a short description above it; this page explains them in detail. DE | EN in the header switches the language.
            

		
            Roles and inheritance
            
		
            
			
            viewer
            Reads files and lists directories.
            
			
            editor
            Everything a viewer can, and writes files, creates and removes files and directories.
            
			
            owner
            Everything an editor can, and gives and revokes grants, restricts directories.
            
		
            
		
            A role comes from a grant directly on a directory, from a grant to a group the actor belongs to, or from a directory above: roles apply to everything below. Several ways add up; revoking one takes away only that one. A workspace is visible exactly when one has at least viewer on its top. Without access, every path in it answers like a path that does not exist.
            

		
            IDs: choose or generate
            
		
            Fields that take an ID offer a list while you type or when you click into them: the actors (by the kind chosen beside the field), the groups, the agent hosts enrolled for this tenant, and local as the issuer of password sign-in. An administrator gets the full lists; anyone else gets the subjects of the grants shown. You can always type a new value instead. Generate fills in an ID: the actor ID from the username or agent ID if one is entered, otherwise a new random one; for an agent also a new agent ID, which its host must then use. The home name follows the actor ID until you change it.
            

		
            Header
            
		
            
			
            You in tenant
            Your actor ID and the tenant (an isolated organisation or team) you are signed in to.
            
			
            Administration
            Opens the tenant administration below; shown to tenant administrators only.
            
			
            Switch tenant
            Signs in again; if your sign-in belongs to several tenants, you choose one.
            
			
            Sign out
            Ends this session on this device.
            
			
            DE | EN, ☾ / ☀ and the palette
            Language, dark or light mode and the colours of the PHI-SPACES palettes; kept in this browser.
            
		
            

		
            Workspaces and files
            
		
            
			
            Workspaces
            Every workspace you see. A click opens it; the line below shows where you are, .. goes up one directory. A directory marked (restricted) does not inherit roles from above.
            
			
            name, New file, New directory
            Creates an empty file or a directory in the directory shown. Names are case-sensitive, have no slash and are not . or ..; you need editor there.
            
		
            

		
            Grants on this directory
            
		
            
			
            The list
            Who holds which role directly on this directory, e.g. editor: group:north#member (every member of the group north). Only owners see it.
            
			
            Role (viewer, editor, owner)
            The role to give or take back. A viewer grant below the top of a workspace is refused: viewer on the top already reaches everything below.
            
			
            Kind (user, agent, group)
            Who receives the role: one person, one agent instance, or every member of a group.
            
			
            actor ID / group
            The actor's ID as the tenant's actor list shows it (without user: or agent:), or the group's name.
            
			
            Grant / Revoke
            Gives the role, or takes back exactly this grant. Every workspace keeps at least one direct owner, so the last one cannot be revoked.
            
			
            Restrict / Unrestrict
            Below the top of a workspace: a restricted directory takes no viewer or editor roles from above, only owners from above keep it; who else should reach it needs a grant on it. Unrestrict lets the roles from above pass again.
            
		
            

		
            Editing a file
            
		
            
			
            Save
            Saves your text over the version you opened. If someone else saved in between, the save is refused as a conflict and your text stays in the editor.
            
			
            Load their version
            After a conflict: shows the newer version; you then decide whether to save your text over it.
            
			
            Close
            Closes the file; asks first if there are unsaved changes.
            
			
            Remove file
            Deletes the file; refused if someone saved a newer version than yours.
            
		
            
		
            Files that are not text are downloaded instead of opened.
            

		
            Tenant administration
            
		
            Only for tenant administrators. Being an administrator gives no rights on files: an administrator reads a workspace only with a grant like anyone else.
            
		
            
			
            Register an actor: user / agent
            user is a person who signs in in the browser, agent an agent instance that works through an agent host (a program that connects to this service and acts for its agents).
            
			
            issuer / host peer ID
            For a user: who confirms the sign-in. With username and password this is local; with an OpenID provider, its issuer URL. For an agent: the peer ID of the agent host it runs on. A host gets its peer ID when the host operator enrolls it (operator enroll-host <peer> <tenant>); the list offers the hosts enrolled for this tenant.
            
			
            subject / agent ID
            For a user: who the person is at that issuer, with username and password the username (lower case). For an agent: the agent ID its host gives it; Generate makes a new one.
            
			
            actor ID
            The ID the actor has in this tenant, used in grants and groups: 1 to 128 characters of A-Z a-z 0-9 _ . : -. An ID is never reused, even after the actor is deleted. Generate takes the username or agent ID, or makes a new one.
            
			
            home name
            The name of the workspace the actor gets for itself, created in the same step with the actor as its owner; it follows the actor ID until you change it.
            
			
            Register
            Creates the actor and its home. A user signing in with username and password also needs a password; the host operator sets it on the server: npm --prefix spaces-files run docker:operator -- set-password <username>.
            
			
            Group membership: group
            The group's name. A group needs no creating: a new name makes a new group, which exists as long as it has members or grants.
            
			
            user / agent / group, actor ID / group
            Who joins or leaves: an actor by its ID, or every member of another group by the group's name (groups nest up to 4 levels; a group cannot contain itself).
            
			
            Add / Remove
            A member gets every role the group holds; removing ends the access that came through the group at once, also for files already open.
            
			
            Create a workspace: name
            A new shared workspace. Names starting with @ are reserved for read-only mounts.
            
			
            user / agent, owner's actor ID
            Its first owner, who then gives the further grants.
            
			
            Actors, Groups
            Every actor of the tenant with its state (enabled, disabled) and every group.
            
		
            
		
            Every change is applied once, even if a reply is lost on the way and the page sends it again.
            
	
            
	
            
		
            spaces-files verwaltet Dateien für Menschen und Agenten-Instanzen. Jeder Mensch und jeder Agent ist ein Akteur mit einer eigenen ID und einem Home, seinem eigenen Workspace. Gemeinsame Arbeit liegt in Workspaces, Verzeichnissen ganz oben. Fährt man über ein Feld oder klickt hinein, erscheint darüber eine kurze Beschreibung; hier steht alles ausführlich. DE | EN in der Kopfzeile wechselt die Sprache.
            

		
            Rollen und Vererbung
            
		
            
			
            viewer
            Liest Dateien und listet Verzeichnisse.
            
			
            editor
            Alles, was ein viewer kann, und schreibt Dateien, legt Dateien und Verzeichnisse an und löscht sie.
            
			
            owner
            Alles, was ein editor kann, und vergibt und entzieht Rechte, schränkt Verzeichnisse ein.
            
		
            
		
            Eine Rolle kommt aus einem Recht direkt auf einem Verzeichnis, aus einem Recht für eine Gruppe, zu der der Akteur gehört, oder von einem Verzeichnis darüber: Rollen gelten für alles darunter. Mehrere Wege addieren sich; ein Entzug nimmt nur genau diesen einen weg. Ein Workspace ist genau dann sichtbar, wenn man mindestens viewer auf seiner obersten Ebene hat. Ohne Zugang antwortet jeder Pfad darin wie ein Pfad, den es nicht gibt.
            

		
            IDs: auswählen oder erzeugen
            
		
            Felder für eine ID bieten beim Tippen oder beim Hineinklicken eine Liste an: die Akteure (nach der daneben gewählten Art), die Gruppen, die für diesen Tenant eingeschriebenen Agenten-Hosts und local als Issuer der Passwort-Anmeldung. Ein Administrator bekommt die vollständigen Listen, alle anderen die Subjekte der angezeigten Rechte. Man kann immer auch einen neuen Wert eintippen. Erzeugen trägt eine ID ein: die Akteur-ID aus dem Benutzernamen bzw. der Agent-ID, wenn eingetragen, sonst eine neue zufällige; bei einem Agenten auch eine neue Agent-ID, die sein Host dann verwenden muss. Der Home-Name folgt der Akteur-ID, bis du ihn änderst.
            

		
            Kopfzeile
            
		
            
			
            Du in Tenant
            Deine Akteur-ID und der Tenant (eine abgeschlossene Organisation oder ein Team), in dem du angemeldet bist.
            
			
            Verwaltung
            Öffnet unten die Tenant-Verwaltung; nur für Tenant-Administratoren sichtbar.
            
			
            Tenant wechseln
            Meldet neu an; gehört deine Anmeldung zu mehreren Tenants, wählst du einen.
            
			
            Abmelden
            Beendet diese Sitzung auf diesem Gerät.
            
			
            DE | EN, ☾ / ☀ und die Palette
            Sprache, dunkler oder heller Modus und die Farben der PHI-SPACES-Paletten; bleiben in diesem Browser gespeichert.
            
		
            

		
            Workspaces und Dateien
            
		
            
			
            Workspaces
            Jeder Workspace, den du siehst. Ein Klick öffnet ihn; die Zeile darunter zeigt, wo du bist, .. geht ein Verzeichnis hinauf. Ein als (restricted) markiertes Verzeichnis erbt keine Rollen von oben.
            
			
            Name, Neue Datei, Neues Verzeichnis
            Legt im gezeigten Verzeichnis eine leere Datei oder ein Verzeichnis an. Groß-/Kleinschreibung zählt, kein Schrägstrich, nicht . oder ..; du brauchst dort editor.
            
		
            

		
            Rechte auf diesem Verzeichnis
            
		
            
			
            Die Liste
            Wer welche Rolle direkt auf diesem Verzeichnis hat, z. B. editor: group:north#member (jedes Mitglied der Gruppe north). Nur owner sehen sie.
            
			
            Rolle (viewer, editor, owner)
            Die Rolle, die vergeben oder zurückgenommen wird. Ein viewer-Recht unterhalb der obersten Ebene wird abgelehnt: viewer oben reicht schon für alles darunter.
            
			
            Art (user, agent, group)
            Wer die Rolle bekommt: eine Person, eine Agenten-Instanz oder jedes Mitglied einer Gruppe.
            
			
            Akteur-ID / Gruppe
            Die ID des Akteurs, wie die Akteur-Liste sie zeigt (ohne user: oder agent:), oder der Name der Gruppe.
            
			
            Vergeben / Entziehen
            Vergibt die Rolle oder nimmt genau dieses Recht zurück. Jeder Workspace behält mindestens einen direkten owner; den letzten kann man nicht entziehen.
            
			
            Einschränken / Freigeben
            Unterhalb der obersten Ebene: ein eingeschränktes Verzeichnis übernimmt keine viewer- oder editor-Rollen von oben, nur die owner darüber behalten es; wer es sonst erreichen soll, braucht ein Recht darauf. Freigeben lässt die Rollen von oben wieder durch.
            
		
            

		
            Eine Datei bearbeiten
            
		
            
			
            Speichern
            Speichert deinen Text über die Version, die du geöffnet hast. Hat inzwischen jemand anderes gespeichert, wird das als Konflikt abgelehnt, und dein Text bleibt im Editor.
            
			
            Deren Version laden
            Nach einem Konflikt: zeigt die neuere Version; dann entscheidest du, ob dein Text darüber gespeichert wird.
            
			
            Schließen
            Schließt die Datei; fragt vorher, wenn Änderungen nicht gespeichert sind.
            
			
            Datei löschen
            Löscht die Datei; abgelehnt, wenn jemand eine neuere Version als deine gespeichert hat.
            
		
            
		
            Dateien, die kein Text sind, werden heruntergeladen statt geöffnet.
            

		
            Tenant-Verwaltung
            
		
            Nur für Tenant-Administratoren. Administrator zu sein gibt keine Rechte auf Dateien: auch ein Administrator liest einen Workspace nur mit einem Recht darauf.
            
		
            
			
            Akteur anlegen: user / agent
            user ist eine Person, die sich im Browser anmeldet, agent eine Agenten-Instanz, die über einen Agenten-Host arbeitet (ein Programm, das sich mit diesem Dienst verbindet und für seine Agenten handelt).
            
			
            Issuer / Host-Peer-ID
            Bei einem Benutzer: wer die Anmeldung bestätigt. Mit Benutzername und Passwort ist das local, mit einem OpenID-Anbieter dessen Issuer-URL. Bei einem Agenten: die Peer-ID des Agenten-Hosts, auf dem er läuft. Ein Host bekommt seine Peer-ID, wenn der Host-Operator ihn einschreibt (operator enroll-host <peer> <tenant>); die Liste zeigt die für diesen Tenant eingeschriebenen Hosts.
            
			
            Subject / Agent-ID
            Bei einem Benutzer: wer die Person bei diesem Issuer ist, mit Benutzername und Passwort der Benutzername (klein geschrieben). Bei einem Agenten: die Agent-ID, die sein Host ihm gibt; Erzeugen macht eine neue.
            
			
            Akteur-ID
            Die ID des Akteurs in diesem Tenant, benutzt in Rechten und Gruppen: 1 bis 128 Zeichen aus A-Z a-z 0-9 _ . : -. Eine ID wird nie wiederverwendet, auch nicht nach dem Löschen des Akteurs. Erzeugen übernimmt den Benutzernamen bzw. die Agent-ID oder macht eine neue.
            
			
            Home-Name
            Der Name des Workspace, den der Akteur für sich bekommt, im selben Schritt angelegt mit dem Akteur als owner; er folgt der Akteur-ID, bis du ihn änderst.
            
			
            Anlegen
            Legt den Akteur und sein Home an. Ein Benutzer mit Passwort-Anmeldung braucht außerdem ein Passwort; das setzt der Host-Operator auf dem Server: npm --prefix spaces-files run docker:operator -- set-password <benutzername>.
            
			
            Gruppenmitgliedschaft: Gruppe
            Der Name der Gruppe. Eine Gruppe muss nicht angelegt werden: ein neuer Name ergibt eine neue Gruppe, die besteht, solange sie Mitglieder oder Rechte hat.
            
			
            user / agent / group, Akteur-ID / Gruppe
            Wer beitritt oder austritt: ein Akteur über seine ID oder jedes Mitglied einer anderen Gruppe über deren Namen (Gruppen bis 4 Ebenen verschachtelt; eine Gruppe kann sich nicht selbst enthalten).
            
			
            Hinzufügen / Entfernen
            Ein Mitglied bekommt jede Rolle der Gruppe; Entfernen beendet den Zugang über die Gruppe sofort, auch für schon geöffnete Dateien.
            
			
            Workspace anlegen: Name
            Ein neuer gemeinsamer Workspace. Namen mit @ am Anfang sind für Read-only-Mounts reserviert.
            
			
            user / agent, Akteur-ID des Owners
            Sein erster owner, der dann die weiteren Rechte vergibt.
            
			
            Akteure, Gruppen
            Jeder Akteur des Tenants mit seinem Zustand (enabled, disabled) und jede Gruppe.
            
		
            
		
            Jede Änderung wird genau einmal ausgeführt, auch wenn eine Antwort unterwegs verloren geht und die Seite sie erneut sendet.
