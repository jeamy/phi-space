# Load test 2026-11-08: 50 and 100 figures, 15 minutes each, big

Measured with `tests/perf/live-load.ts` against the running production on big ([betrieb.en.md](betrieb.en.md), "Load test
against the running world"), commit 38ad9ab: the world in its four regions (west, nord, ost, sued), each region Space on
the Rust space server (`docker:big:rust:up`), world workers, NPCs, model processes and web in TypeScript; the accounts
Space on nano. Guest figures played through the web process on big (loopback port 3900) as pages do: picking up
driftwood and shells, carrying wood to the fire and putting it in, selling shells to Kalle, market, inventory, "wer",
going through the exits, with a pause of 1 to 3 s between two commands. Each command counts from sending to the first
answer for the figure; after 10 s it counts as unanswered. Alongside, every 15 s: CPU and memory of each container
(`docker stats`) and the load average of the machine. One minute of idle was recorded before and after each run. After
each run `live-load-cleanup.ts` removed every figure ("every figure is gone"). Raw data on big in
`~/phi-load/2026-11-08/` (`run.sh`, `bots-50/`, `bots-100/`: `commands.jsonl`, `stats.txt`, `load.log`, `cleanup.log`).

## Result

| | 50 figures | 100 figures |
|---|---|---|
| Commands in 900 s | 21,227 (23.6/s) | 42,209 (46.9/s) |
| answered | 15,599 ok, 5,558 rejected | 22,357 ok, 19,732 rejected |
| unanswered after 10 s | 70 (0.3 %) | 120 (0.3 %) |
| Response median | 60 ms | 72 ms |
| Response p90 / p95 / p99 | 94 / 113 / 266 ms | 141 / 166 / 268 ms |
| Space process, busiest region: CPU avg (max) | ost 35 % (69 %) | west 57 % (99 %) |
| Web process: CPU avg / memory max | 14 % / 145 MB | 22 % / 212 MB |
| Load average of big (8 cores, 1 min) | avg 4.1, max 5.6 | avg 5.9, max 7.9 |

"Rejected" is a game rule (no path, cell occupied, too far, nothing to sell), not a failure. The unanswered are all walks
(`move x y`): the game sends nothing to a step onto the figure's own position, as on 2026-10-28; none of them is waiting.
Before the test, with the other services on big, the load average stood at 2.8.

**No bottleneck at 100 figures.** The busiest Space process (west, where the start bay is) used about half a core on
average and touched a whole core only briefly; the others stayed lower, sued (fewest figures) at 13 %. World workers
used 3 to 10 %, NPCs about 1 %, the model processes nothing (the figures never speak freely). For many more figures the
machine is the limit before any single process: at 100 figures big reached a load of 7.9 on its 8 cores, a share of
which belongs to the other services there.

## Against 2026-10-28

| | 2026-10-28, 100 figures, 600 s | 2026-11-08, 100 figures, 900 s |
|---|---|---|
| Setup | one world Space on nano, TypeScript | four region Spaces on big, Rust |
| Commands per second | 12.8 | 46.9 |
| Response median / p95 | 4,280 / 9,116 ms | 72 / 166 ms |
| unanswered after 10 s | 25 % | 0.3 % |
| Space process CPU | avg 108 %, max 123 % (saturated) | busiest avg 57 %, max 99 % |

The two runs differ in more than the server: since then the world was split into regions on big
([welt-aufteilen.en.md](welt-aufteilen.en.md)), the world workers read from a mirror, a command costs fewer calls
([betrieb.en.md](betrieb.en.md), status after the load test), and the region Spaces run on the Rust server
([../../docs/rust-portierung.en.md](../../docs/rust-portierung.en.md)). The figures now get their answers so quickly
that they send almost four times as many commands in the same time (the pause between two commands is the same).
